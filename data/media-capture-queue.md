## Capture tooling (2026-07-12)

- `node scripts/capture.mjs record <url> <out.mp4>` — video from any live page.
  `--scroll` takes are STOP-MOTION (one screenshot per frame at exact eased
  positions — perfectly smooth, ~90s per take); `--to 0.25` pans the top quarter.
  Non-scroll takes (animations/interactions) use live CDP screencast; browsers
  only paint ~20 unique scroll positions/sec live, hence the split.
- `upload` now handles video (`.mp4/.webm/.mov/.gif` → resource_type video).
- `![alt](….mp4)` in project md now renders as a muted looping `<video>` with a
  Cloudinary poster frame (remarkEnhanceImages) — embed videos like images.
- `vhs` is installed for terminal-tool gifs (`capture.mjs tui` or hand-written tapes).
- Capture-Chrome gotcha: pages sending HSTS headers (nuxt-security apps) poison
  the throwaway profile — `rm -rf /tmp/capture-chrome-9333` if localhost breaks.
- WebGL apps render headlessly now (SwiftShader flags baked into capture.mjs).
  `record --eval "<js>"` runs a script mid-take to trigger animations — DOM-click
  buttons (synthetic KeyboardEvents get ignored, el.click() works).
